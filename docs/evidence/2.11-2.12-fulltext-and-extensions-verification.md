## 2.11 — Full-text search (GIN + pg_trgm)

### Objetivo

Criar índices full-text no PostgreSQL para busca textual eficiente em:
- `Club.name`, `Club.fullName`, `Club.shortName`
- `Player.fullName`, `Player.shortName`
- `Competition.name`

### Implementação

**Arquivo: `apps/api/prisma/fulltext-indexes.sql`**

Cria:
1. **Colunas `search_vector` (tsvector)** já declaradas no schema.prisma como `Unsupported("tsvector")?` em `Club`, `Player`, `Competition`
2. **Índices GIN** em `search_vector` para busca textual com `tsquery` (suporte a stemming, stopwords)
3. **Triggers `BEFORE INSERT OR UPDATE`** que populam `search_vector` combinando campos com pesos (A > B > C) e usando stemmer português (`to_tsvector('portuguese', ...)`)
4. **Índices trigram (`gin_trgm_ops`)** em `Club.name`, `Club.fullName`, `Player.fullName`, `Competition.name` para busca fuzzy por similaridade (ex.: "Flamengu" encontra "Flamengo")
5. **UPDATE retroativo** para popular colunas `search_vector` já existentes (triggers só disparam em INSERT/UPDATE futuros)

### Decisões técnicas

#### 1. `Unsupported("tsvector")?` no schema.prisma
Prisma 5.22 não suporta `tsvector` como tipo declarado. A solução é declarar a coluna como `Unsupported("tsvector")?` — Prisma Client sabe que a coluna existe mas não permite queries diretas nela. As queries full-text são feitas via `$queryRaw`:

```typescript
const results = await prisma.$queryRaw`
  SELECT id, name FROM clubs
  WHERE search_vector @@ plainto_tsquery('portuguese', ${query})
  ORDER BY ts_rank(search_vector, plainto_tsquery('portuguese', ${query})) DESC
  LIMIT 20
`;
```

#### 2. Pesos A/B/C para ranking de relevância
```sql
setweight(to_tsvector('portuguese', name), 'A')      -- peso alto (nome curto)
setweight(to_tsvector('portuguese', fullName), 'B')  -- peso médio (nome completo)
setweight(to_tsvector('portuguese', shortName), 'C')  -- peso baixo (sigla)
```
Busca por "Flamengo" prioriza match em `name` (A) sobre `fullName` (B) sobre `shortName` (C).

#### 3. Stemmer português
`to_tsvector('portuguese', ...)` aplica stemmer correto:
- "jogando" → "jogar"
- "clubes" → "club"
- "brasileiros" → "brasileir"

Permite buscar "jogar" e encontrar registros com "jogando".

#### 4. Trigram (pg_trgm) para busca fuzzy
Índices GIN com `gin_trgm_ops` permitem:
```sql
SELECT * FROM clubs WHERE name % 'Flamengu';  -- similaridade > threshold
SELECT * FROM clubs WHERE similarity(name, 'Flamengu') > 0.3;
```
Cobre casos de typos e aproximações que o tsvector não pega.

#### 5. Trigger BEFORE INSERT OR UPDATE
Sempre que um `Club` é criado/atualizado, o trigger recalcula `search_vector`. Aplicação nunca precisa se preocupar em popular essa coluna manualmente.

### Aplicação

Este arquivo **NÃO é executado pelo Prisma** (ele não suporta triggers). Deve ser aplicado via:

```bash
psql "$DATABASE_URL" -f prisma/fulltext-indexes.sql
```

Ou automaticamente via `migrate.ps1` (Tarefa 2.13).

### SQLite (sandbox)
**NÃO aplicável.** SQLite não suporta tsvector nem pg_trgm. No sandbox, buscas textuais usam `LIKE`/`ILIKE` (já implementado em `clubsRepository.findMany`).

## 2.12 — Extensões PostgreSQL

### Objetivo

Garantir que as extensões necessárias estejam ativas no banco antes das migrations e índices full-text.

### Implementação

**Arquivo: `apps/api/prisma/extensions.sql`**

```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";  -- UUID v4
CREATE EXTENSION IF NOT EXISTS pgcrypto;       -- hash, gen_random_bytes
CREATE EXTENSION IF NOT EXISTS pg_trgm;        -- busca trigram (Tarefa 2.11)
```

### Decisões técnicas

#### 1. `uuid-ossp` para UUIDs
O Prisma usa `@default(uuid())` que internamente chama `gen_random_uuid()` do pgcrypto. Mas `uuid-ossp` fornece `uuid_generate_v4()` para casos onde precisamos gerar UUID fora do Prisma (ex.: ID externo antes do insert).

#### 2. `pgcrypto` para hash futuro
Já fazemos hash de senha com argon2 via Node.js (Tarefa 2.7). Mas pgcrypto é necessário para:
- `gen_random_uuid()` (alternativa ao uuid-ossp)
- Hash de colunas sensíveis se migrarmos crypto para o banco (futuro, ex.: encrypted PII)

#### 3. `pg_trgm` para busca fuzzy
Habilita operador `%` (similaridade) e função `similarity()`. Usado nos índices trigram (Tarefa 2.11).

### Idempotência
`CREATE EXTENSION IF NOT EXISTS` é idempotente. Pode ser executado múltiplas vezes sem erro.

### Aplicação

```bash
psql "$DATABASE_URL" -f prisma/extensions.sql
```

Ou automaticamente via `migrate.ps1` (Tarefa 2.13) — sempre executado ANTES da migration Prisma.
