## Idempotência

- **Clubes:** `upsert` por `name_country` (já existe `@@unique([name, country])`)
- **Competições:** `findFirst` por `name+country` + `update` ou `create` (não há `@@unique` em name)
- **Rankings:** `findFirst` por `name` + `update` ou `create` (não há `@@unique` em name)
- **RankingEntries:** `deleteMany` por `rankingId` seguido de `create` (recria sempre, garantindo estado final consistente)

## Sanity checks pós-seed

```typescript
if (clubs < 10) throw new Error(`Esperado ≥10 clubes, atual ${clubs}`);
if (competitions < 3) throw new Error(`Esperado ≥3 competições, atual ${competitions}`);
if (rankings < 2) throw new Error(`Esperado ≥2 rankings, atual ${rankings}`);
if (rankingEntries < 20) throw new Error(`Esperado ≥20 entries (10x2), atual ${rankingEntries}`);
```

## Decisões técnicas

### 1. Pontos de ranking: aproximação realista, não oficial
Os valores de pontos (ex.: Palmeiras 2848 pts no Ranking CBF 2023) são **aproximações realistas** baseadas em métodos públicos da CBF/CONMEBOL, não valores oficiais. Justificativa: o objetivo do seed é ter dados realistas para testar queries, dashboards e ranking de clubes — não servir como fonte oficial de verdade. Quando o pipeline ETL (Fase 6.4) estiver pronto, ele substituirá esses valores por dados reais das fontes oficiais.

### 2. Copa Libertadores com `country=null`
É uma competição continental (CONMEBOL), não nacional. Por isso `country: null` no seed. O campo `country` é `String?` para permitir isso.

### 3. RankingEntries: estratégia deleteMany + create
Em vez de `upsert` por `@@unique([rankingId, clubId])`, optei por `deleteMany({where: {rankingId}})` seguido de `create` em loop. Motivos:
- Mais simples e legível que upsert em loop
- Garante estado final idêntico ao esperado (sem entradas órfãs caso o seed mude)
- Como o seed roda poucas vezes (config, não hot path), o custo de recriar é aceitável

### 4. Busca por `contains: 'Libertadores'`
Para evitar problemas com acentuação ("América" vs "America"), busco competições que contenham "Libertadores" no nome. Mais robusto que comparar string completa.
