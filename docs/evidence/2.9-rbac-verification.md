## Objetivo

Implementar Role-Based Access Control com:
- 3 roles padrão (admin, pro, free)
- 18 permissões granulares (formato `<resource>:<action>`)
- Atribuição role-permissão no seed
- Helper para verificação em runtime (com cache em memória)

## Decisões técnicas

### 1. Permissões como strings hierárquicas `<resource>:<action>`
Padrão usado por GitHub Actions, AWS IAM, Kubernetes RBAC. Vantagens:
- Legíveis: `clubs:write` é auto-explicativo
- Extensíveis: adicionar `clubs:import` não quebra permissões existentes
- Indexáveis: `permissions.name @unique` + índice em `audit_logs.action`

### 2. Cache em memória por processo (TTL 5 min)
```typescript
const permissionsCache = new Map<string, { permissions: Set<string>; expiresAt: number }>();
const CACHE_TTL_MS = 5 * 60 * 1000;
```

- Lookup de permissões é **hot path** (toda request autenticada checa permissão)
- Sem cache: query Prisma com 4 joins a cada request = ~5-10ms
- Com cache: ~0.01ms (Map.get)

**Limitação:** em multi-instance (PM2 cluster, Kubernetes replicas), o cache é por processo. Após `assignRole`, outras instâncias ainda podem usar permissões antigas por até 5 min. Solução futura (Fase 6.3): Redis pub/sub para invalidar cache cross-instance.

### 3. `assignRole` idempotente via `upsert`
```typescript
await prisma.userRole.upsert({
  where: { userId_roleId: { userId, roleId: role.id } },
  update: {},  // nada a atualizar se já existe
  create: { userId, roleId: role.id },
});
```

Chamar `assignRole` 2x para mesma (user, role) não falha nem duplica.

### 4. `invalidateUserPermissionsCache` chamado após `assignRole/revokeRole`
Garante que próxima chamada a `getUserPermissions` refaz a query.

### 5. `getUserPermissions` retorna `Set<string>` (não array)
Set é a estrutura correta para checagem `has()` em O(1). Array seria O(n).

### 6. Multiplas roles por usuário (permissões se somam via union)
Um usuário com roles `pro` + `admin` tem a **união** das permissões (não interseção). Implementado porque o Set naturalmente deduplica. Caso de uso: admin temporário que mantém seu plano `pro`.
