## Objetivo

Criar helpers para gerenciar assinaturas SaaS (FREE/PRO/ELITE) e histórico de cobranças.

## Implementação

### Arquivo: `apps/api/src/modules/billing/subscription.service.ts`

**Constantes:**
- `PLAN_PRICES_CENTS`: `{ FREE: 0, PRO: 2900, ELITE: 9900 }` (centavos de BRL)
- `PLAN_CYCLE_DAYS`: 30 (mensal)

**Funções de Subscription:**
| Função | Propósito |
|--------|-----------|
| `createFreeSubscription(userId)` | Cria assinatura FREE inicial (idempotente) |
| `getSubscription(userId)` | Retorna assinatura do usuário |
| `changePlan(userId, newPlan)` | Troca plano (upgrade/downgrade) |
| `cancelSubscription(userId)` | Marca CANCELLED sem reverter plano |
| `isActiveSubscription(userId)` | Boolean (status + dentro do período) |
| `hasMinimumPlan(userId, minPlan)` | Verifica hierarquia FREE < PRO < ELITE |

**Funções de Billing:**
| Função | Propósito |
|--------|-----------|
| `createBilling(input)` | Cria registro PENDING (idempotência webhook) |
| `markBillingPaid(billingId)` | PAID + renova currentPeriodEnd (transação) |
| `refundBilling(billingId)` | REFUNDED sem reverter período |
| `failBilling(billingId)` | FAILED (pagamento recusado) |
| `listUserBillings(userId, options)` | Lista cobranças com filtro e paginação |
| `findBillingByExternalId(externalId)` | Busca por ID do provedor (webhook idempotência) |

## Decisões técnicas

### 1. Valores em centavos (int), não em reais (float)
`amountCents: 2900` em vez de `amount: 29.00`. Float tem problema de precisão (0.1 + 0.2 = 0.30000000000000004). Centavos são exatos e aceitos por todos os provedores de pagamento.

### 2. `markBillingPaid` é transacional (atomicidade)
Usa `prisma.$transaction(async (tx) => { ... })` para garantir que billing e subscription sejam atualizados juntos. Se um falhar, ambos rollback. Importante: se billing virou PAID mas subscription.currentPeriodEnd não foi renovado, usuário pagou mas perdeu acesso.

### 3. `cancelSubscription` mantém `currentPeriodEnd`
Após cancelar, usuário continua com acesso até o fim do ciclo já pago. Job futuro (Fase 9.x) muda `status → EXPIRED` e `plan → FREE` quando `currentPeriodEnd` expira.

### 4. `hasMinimumPlan` para feature gating
Permite verificar "apenas PRO+ pode usar este recurso" sem expor o plano do usuário ao caller. Hierarquia é hardcoded como `['FREE', 'PRO', 'ELITE']` (índice 0 < 1 < 2).

### 5. `findBillingByExternalId` para idempotência webhook
Webhook do provedor pode chamar a mesma cobrança várias vezes (retry). Antes de processar, buscar por `externalId` — se já existe e está PAID, ignorar.

### 6. Tipos locais (não importar de @prisma/client)
Defini tipos locais (`Subscription`, `Billing`, `SubscriptionPlan`, etc.) em vez de importar de `@prisma/client`. Motivo: o schema SQLite usa `String` para esses campos (não tem enums), então os tipos do Prisma divergem entre PostgreSQL (enums) e SQLite (strings). Tipos locais com cast `as unknown as T` funcionam para ambos.

## Preços definidos

| Plano | Preço mensal | Em centavos |

| FREE | R$ 0,00 | 0 |
| PRO | R$ 29,00 | 2900 |
| ELITE | R$ 99,00 | 9900 |

Ciclo: 30 dias. `currentPeriodEnd` = data de fim do ciclo atual. Renovado automaticamente quando webhook confirma pagamento.
