## Decisões técnicas

### 1. AuditLog polimórfico (sem FK para Club/Player/etc.)
**Por que:** AuditLog rastreia mudanças em múltiplas entidades (User, Club, Subscription, etc.). Uma FK explícita para cada uma geraria N colunas opcionais. Em vez disso, usamos `entityType` (string) + `entityId` (string) + índice composto `@@index([entityType, entityId])`.
**Trade-off:** Perde integridade referencial ao nível do banco, mas ganha flexibilidade. Aplicação deve garantir que `entityType` seja válido.

### 2. `Unsupported("tsvector")` para busca full-text
**Por que:** Prisma 5.22 não suporta declarativamente índices GIN/pg_trgm. Adicionamos a coluna `search_vector` como `Unsupported("tsvector")?` em `Club`, `Player`, `Competition` para que o Prisma Client saiba que ela existe (mesmo sem poder ser queryada). O SQL dos índices fica em `fulltext-indexes.sql` (Tarefa 2.11).

### 3. SQLite como espelho funcional
**Por que:** O sandbox Linux não tem Docker/PostgreSQL. Mantemos `schema.sqlite.prisma` idêntico em estrutura, mas:
- Enums viram `String` + validação no domínio
- `Unsupported("tsvector")` é removido (SQLite não tem)
- `@db.VarChar(N)` e `@db.Char(N)` são removidos
- `Json?` vira `String?` (JSON string)

### 4. `AuditLog.user` com `onDelete: SetNull`
**Por que:** Mesmo se um usuário for deletado, queremos preservar o histórico de auditoria. `SetNull` mantém o registro com `userId = null`.

### 5. `RankingEntry` com `@@unique([rankingId, position])`
**Por que:** Garante que não existam duas posições com mesmo número no mesmo ranking. Junto com `@@unique([rankingId, clubId])` (não repetir clube no mesmo ranking), garantimos a integridade do ranking a nível de banco.

## Verificação executada

```bash
# 1. Validar sintaxe do schema PostgreSQL
DATABASE_URL="postgresql://x:x@localhost:5432/x" prisma validate --schema=prisma/schema.prisma
# → "The schema at prisma/schema.prisma is valid 🚀"

# 2. Validar sintaxe do schema SQLite
prisma validate --schema=prisma/schema.sqlite.prisma
# → "The schema at prisma/schema.sqlite.prisma is valid 🚀"

# 3. Gerar Prisma Client a partir do schema SQLite (sandbox)
prisma migrate dev --schema=prisma/schema.sqlite.prisma --name init_almanaque_v2
# → "Applying migration `20260720202741_init_almanaque_v2`"
# → "Your database is now in sync with your schema."
# → "✔ Generated Prisma Client (v5.22.0)"

# 4. Confirmar contagem de artefatos SQL gerados
prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.sqlite.prisma --script | grep -i "CREATE TABLE" | wc -l
# → 14 (Club, Player, Competition, Ranking, RankingEntry, User, Session, Role, Permission, UserRole, RolePermission, Subscription, Billing, AuditLog)

prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.sqlite.prisma --script | grep -iE "CREATE TABLE|CREATE UNIQUE|CREATE INDEX" | wc -l
# → 52 (14 tabelas + índices + constraints unique)

# 5. Typecheck
tsc --noEmit
# → EXIT 0
```
