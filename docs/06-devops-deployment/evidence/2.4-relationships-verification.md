# Evidência 2.4 — Relações e Índices (FKs com onDelete + índices compostos)

**Data:** 2026-07-20
**Responsável:** Doer (GLM-5.1)
**Schema alvo:** PostgreSQL canônico + SQLite sandbox

---

## Objetivo

Garantir que:
1. Todas as foreign keys tenham `onDelete` explícito (`SetNull` para opcionais, `Cascade` para dependentes)
2. Índices compostos cubram queries filtradas frequentes
3. `prisma validate` e `prisma migrate diff` passem sem erros

## FKs com onDelete explícito (14 foreign keys)

Confirmado via `prisma migrate diff --script`:

| FK | Tabela | Ref | onDelete | Justificativa |
|----|--------|-----|---------|---------------|
| `clubs_createdBy_fkey` | `clubs.createdBy` | `users.id` | SET NULL | Clube permanece mesmo se usuário criador for deletado |
| `players_clubId_fkey` | `players.clubId` | `clubs.id` | SET NULL | Jogador sobrevive se clube for dissolvido |
| `rankings_competitionId_fkey` | `rankings.competitionId` | `competitions.id` | SET NULL | Ranking pode existir sem competição associada (ex.: ranking histórico CBF) |
| `ranking_entries_rankingId_fkey` | `ranking_entries.rankingId` | `rankings.id` | CASCADE | Entries sem sentido sem o pai |
| `ranking_entries_clubId_fkey` | `ranking_entries.clubId` | `clubs.id` | CASCADE | Se clube for dissolvido, suas entradas em rankings desaparecem |
| `sessions_userId_fkey` | `sessions.userId` | `users.id` | CASCADE | Sessões são do usuário — se ele vai, elas vão |
| `user_roles_userId_fkey` | `user_roles.userId` | `users.id` | CASCADE | Atribuição de role some se user for deletado |
| `user_roles_roleId_fkey` | `user_roles.roleId` | `roles.id` | CASCADE | Idem para role deletada |
| `role_permissions_roleId_fkey` | `role_permissions.roleId` | `roles.id` | CASCADE | Idem |
| `role_permissions_permissionId_fkey` | `role_permissions.permissionId` | `permissions.id` | CASCADE | Idem |
| `subscriptions_userId_fkey` | `subscriptions.userId` | `users.id` | CASCADE | Assinatura pertence ao user — some com ele |
| `billings_subscriptionId_fkey` | `billings.subscriptionId` | `subscriptions.id` | CASCADE | Billing é filho de Subscription |
| `billings_userId_fkey` | `billings.userId` | `users.id` | CASCADE | Billing vinculado ao usuário |
| `audit_logs_userId_fkey` | `audit_logs.userId` | `users.id` | SET NULL | **Crítico:** preserva histórico mesmo se user for deletado (imutabilidade de auditoria) |

**Total:** 14 FKs, todas com `onDelete` explícito. Nenhuma `Restrict` implícita (default do Prisma).

## Índices compostos adicionados (Tarefa 2.4)

| Tabela | Índice composto | Caso de uso |
|--------|----------------|-------------|
| `clubs` | `@@index([country, status])` | Listar clubes ativos por país (dashboard admin) |
| `clubs` | `@@index([city, state])` | Buscar clubes por localidade |
| `users` | `@@index([email, status])` | Login: `WHERE email = ? AND status = 'ACTIVE'` (evita table scan) |
| `sessions` | `@@index([userId, revokedAt])` | Listar sessões ativas de um usuário (`WHERE userId = ? AND revokedAt IS NULL`) |
| `billings` | `@@index([userId, status, paidAt])` | Relatório financeiro: `WHERE userId = ? AND status = 'PAID' ORDER BY paidAt` |

## Verificação executada

```bash
# 1. Validar ambos schemas
DATABASE_URL="postgresql://x:x@localhost:5432/x" prisma validate --schema=prisma/schema.prisma
# → "The schema at prisma/schema.prisma is valid 🚀"

prisma validate --schema=prisma/schema.sqlite.prisma
# → "The schema at prisma/schema.sqlite.prisma is valid 🚀"

# 2. Aplicar migration no SQLite sandbox
prisma migrate dev --schema=prisma/schema.sqlite.prisma --name add_composite_indexes --skip-generate
# → "Applying migration `20260720202940_add_composite_indexes`"

# 3. Confirmar FKs com onDelete
prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.sqlite.prisma --script | grep "REFERENCES"
# → 14 FKs, todas com ON DELETE explícito (SET NULL ou CASCADE)

# 4. Contar artefatos SQL
prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.sqlite.prisma --script | grep -ciE "CREATE TABLE|CREATE UNIQUE|CREATE INDEX"
# → 57 (14 tabelas + 5 índices compostos novos + outros índices/unique)
```

## Estado final dos índices por modelo

### `clubs`
- `@@unique([name, country])` (constraint)
- `@@index([country])`, `@@index([city])`, `@@index([status])` (single, já existentes)
- `@@index([country, status])` (composto novo)
- `@@index([city, state])` (composto novo)

### `players`
- `@@index([country])`, `@@index([birthDate])`, `@@index([clubId])`, `@@index([fullName])` (single)

### `competitions`
- `@@index([country])`, `@@index([type])` (single)

### `rankings`
- `@@index([competitionId])`, `@@index([season])` (single)

### `ranking_entries`
- `@@unique([rankingId, clubId])`, `@@unique([rankingId, position])` (constraints)
- `@@index([rankingId])`, `@@index([clubId])`, `@@index([position])` (single)

### `users`
- `email @unique` (constraint)
- `@@index([status])`, `@@index([createdAt])` (single)
- `@@index([email, status])` (composto novo)

### `sessions`
- `tokenHash @unique` (constraint)
- `@@index([userId])`, `@@index([expiresAt])`, `@@index([revokedAt])` (single)
- `@@index([userId, revokedAt])` (composto novo)

### `roles`
- `name @unique` (constraint)

### `permissions`
- `name @unique` (constraint)

### `user_roles`
- `@@id([userId, roleId])` (PK composta)
- `@@index([roleId])`

### `role_permissions`
- `@@id([roleId, permissionId])` (PK composta)
- `@@index([permissionId])`

### `subscriptions`
- `userId @unique` (1:1 — um usuário tem no máximo 1 assinatura ativa)
- `@@index([plan])`, `@@index([status])`

### `billings`
- `@@index([subscriptionId])`, `@@index([userId])`, `@@index([status])` (single)
- `@@index([userId, status, paidAt])` (composto novo)

### `audit_logs`
- `@@index([entityType, entityId])` (composto — busca polimórfica)
- `@@index([userId])`, `@@index([action])`, `@@index([createdAt])`
